# PWA and offline

Built on `@ducanh2912/next-pwa` + workbox. Two places hold the behavior:

- **`next.config.ts`** — the `withPWAInit(...)` block: `dest: 'public'`, `customWorkerSrc: 'src/worker'`, `disable` in development, `fallbacks.document: '/offline'`, and the whole `workboxOptions.runtimeCaching` array.
- **`src/worker/index.ts`** — the custom worker: message handling, push, background sync, periodic sync, and the library-add queue.

Client-side queue helpers live in `src/lib/pwa/libraryAddQueue.ts`. The offline page is `src/app/offline/`. Manifest is generated by `src/app/manifest.ts`.

The service worker is **disabled in development**. Any SW change must be verified with `npm run build && npm run start`.

## Caching rules — the ordering matters

`runtimeCaching` is evaluated top-down; the first matching rule wins. Current order and intent:

| # | Pattern | Strategy | Why |
|---|---|---|---|
| 1 | Any request with an `Authorization` header | `NetworkOnly` | Personal data must never be cached |
| 2 | `/api/(auth\|admin)/` | `NetworkOnly` | Same |
| 3 | `/api/me` | `NetworkOnly` | Same |
| 4 | `/api/(articles\|public)/` | `StaleWhileRevalidate` | Public, 10-min expiry |
| 5 | `/_next/static/` | `CacheFirst` | Immutable build output, 1-year |
| 6 | editor chunks (tiptap/lowlight/prosemirror) | `CacheFirst` | Large, rarely changing |
| 7 | public pages | `StaleWhileRevalidate` | |
| 8 | auth-gated pages | `NetworkFirst` | |
| 9 | Supabase `/rest/` | `NetworkFirst` | 5-min fallback |
| 10 | Supabase `/storage/` | `CacheFirst` | 7-day |
| 11 | external media images | `CacheFirst` | 14-day, 500 entries, `purgeOnQuotaError` |

**The three `NetworkOnly` rules must stay first.** Inserting a broader rule above them causes authenticated responses to be cached and served to the wrong user — the single worst failure mode in this app. When adding a rule, add it *below* the auth rules and make its `urlPattern` as narrow as possible.

Never remove `purgeOnQuotaError` from the image caches; without it, low-storage devices throw quota errors instead of evicting.

`skipWaiting: true` + `clientsClaim: true` mean a new worker activates immediately — so a broken worker reaches every user on the next load, with no gradual rollout.

## The library-add queue — do not break

Offline library additions are queued and replayed. Constants in `src/worker/index.ts`:

```
QUEUE_DB_NAME   = 'hobbistas-pwa'
QUEUE_STORE_NAME = 'library-add-queue'   (keyPath 'id', autoIncrement)
LIBRARY_SYNC_TAG = 'library-add-sync'
```

The `sync` event listener drains the store against the add API. Changing the DB name, store name, keyPath, or the sync tag **silently discards whatever is already queued on users' devices** — those additions are simply lost with no error surface. If a change is unavoidable, bump the DB version and migrate in `onupgradeneeded`; do not rename in place.

The same IndexedDB database also holds `diary_offline_drafts` (see `src/lib/diary/offlineStorage.ts`). Any `onupgradeneeded` change must preserve both stores.

## Worker event listeners

`message` (including the logout signal that clears auth caches), `push`, `notificationclick`, `notificationclose`, `sync`, `periodicsync` (feed refresh).

- **Auth cache clearing on logout must stay.** Removing it serves the previous user's cached data after a logout.
- Push handling tracks received/open/dismiss and routes clicks to a target URL — keep all three paths when editing.

## Adding a new external image host

Two places, both required:
1. `next.config.ts` → `images.remotePatterns` (otherwise `next/image` refuses the URL).
2. The external-media-images `urlPattern` in `runtimeCaching`, if it should be cached offline.

## Verifying a PWA change

```
npm run build && npm run start
```
Then in DevTools:
1. Application → Service Workers: confirm the new worker activated.
2. Network → Offline: reload — the `/offline` fallback should render.
3. Add a library item while offline, go back online, confirm it syncs.
4. Log out, then inspect Cache Storage: no authenticated response should remain.

Cypress specs live in `cypress/`; `npm run cypress:open` builds, starts, and opens the runner.
